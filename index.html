# Family Command Center — Phase 6 Kickoff Prompt (Meals) *Paste this into a fresh conversation, within this project, to start this phase.* --- I'm ready to build out a full **Meals** section. Please read `design-spec.md` (§6a, the Home dashboard pattern), `phase1a-recap.md` (the existing Lunch tracker's real implementation), `phase4-5-recap.md` (the kiosk's reserved speech-bubble slot and Lunch paper's planned growth), and the current `index.html` before starting. ## Important framing — this is a restructure, not a rebuild The existing school Lunch tracker (built in Phase 1a) is **not being replaced or duplicated** — it's being relocated. Today it's its own top-level nav tab (`lunch` in `TOP_VIEWS`). It should become a **sub-view inside a new top-level "Meals" tab**, alongside new Recipes, Planner, and Shopping List sub-views. All of Lunch's existing Firestore collections (`schoolLunchMenus`, `lunchPlans`, `lunchOptions`) and logic (PDF import, per-member school/packed choice, the four-category packed-lunch builder) carry over **completely unchanged** — this phase is additive UI + new collections for the other meals, plus a nav reorganization. ## New nav structure ``` TOP_VIEWS: ["home", "outfitHub", "meals", "tasks", "calendar"] ``` `meals` replaces `lunch` as the top-level entry. Inside it, sub-tabs: - **Recipes** — new - **Planner** — new (weekly drag-and-drop, breakfast/dinner/snacks) - **Lunch** — the existing tracker, moved here as-is - **Shopping List** — new ## New collections ### `recipes` Text-only for now — no photo upload this phase. ``` recipes/{recipeId} title: string ingredients: array<{ name: string, amount: number, unit: string, category: string // "produce" | "dairy" | "meat" | "pantry" | "frozen" | "bakery" | "other" — drives shopping list grouping }> instructions: string // free text, can be multi-step/multi-line tags: array // optional, e.g. "quick", "kid-friendly", "slow-cooker" prepTime: string // optional, free text ("30 min") createdAt: timestamp ``` ### `mealPlans` Covers breakfast, dinner, and snacks — **not lunch**, which stays entirely on the existing `lunchPlans` collection. One document per date per meal type (not per member — meals here are household-wide, unlike the per-child lunch tracker). ``` mealPlans/{planId} date: string // "YYYY-MM-DD" mealType: "breakfast" | "dinner" | "snack" source: "recipe" | "freeText" recipeId: string // if source === "recipe" freeText: string // if source === "freeText" — e.g. "leftovers" or "takeout" notes: string ``` ## Features in scope ### Recipes - List/grid of saved recipes, add/edit/delete - Each ingredient entry includes a category (dropdown), so the shopping list can group correctly later ### Weekly Planner - Drag-and-drop weekly calendar, same interaction pattern as the Outfit Planner's weekly grid (reuse that pattern rather than inventing a new one) - Drop targets: breakfast/dinner/snack slots per day; drag sources: saved recipes and a "quick add" free-text option (for leftovers, takeout, etc.) ### Lunch (relocated, unchanged) - Move the existing full Lunch section here verbatim — same month view, same PDF import flow, same per-member packed/school toggle and four-category builder ### Shopping List - Generated from `mealPlans` (resolving `recipeId` → `recipes.ingredients`) across a selected date range (default: current week) - **Grouped by category** (produce, dairy, meat, pantry, etc.) per ingredient's `category` field - Manual "add an item" option for anything outside planned meals (paper towels, etc.) — these need their own lightweight category or just an "other" bucket - Checkable items, same interaction pattern as Routines/Tasks checkboxes ## Home dashboard integration Per §6a of `design-spec.md`: the Home tab's existing "this week pack vs. school lunch" widget should be **broadened into a combined "This week's meals" widget** — lunch (existing data) plus a glance at planned dinners, not two separate widgets competing for space. Tapping through goes to the full Meals section. ## Kitchen Display (kiosk) integration Per `phase4-5-recap.md`, two things were already anticipated for this phase: - The **bottom-left speech bubble** slot (currently reserved, no widget) becomes a **Meal Plan widget** — likely tonight's dinner at a glance. - The **bottom-right paper** (currently the Lunch widget) should **grow to include a Dinner section** alongside the existing per-member lunch display, rather than needing a whole separate slot. ## What's explicitly out of scope this phase - Recipe photos (deferred — text-only for now, per your call) - Nutrition tracking, calorie counts, or any health-data layer - Any change to the AI Assistant phase — still fully deferred, not touched here --- *Once this is confirmed, next step is the nav restructure (renaming `lunch` → `meals` in `TOP_VIEWS`, moving the existing Lunch view into a sub-tab) before any new feature code, since getting that foundation right first avoids reshuffling working Lunch functionality mid-build.*
